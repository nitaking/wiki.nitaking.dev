## 1ファイル1型・1責務

Single Responsibility Principle（単一責任の原則）のファイル単位への適用です。1つのファイルが1つの理由でしか変更されないようにする。repository.goに2つのinterfaceがあると、TargetUserの取得条件を変えるときとWrappedResultの保存契約を変えるときの両方でこのファイルが変わります。

Bad

```
domain/
└── repository.go   // TargetUserRepository と WrappedResultRepository
```

Good

```
domain/
├── target_user_repository.go
└── wrapped_result_repository.go
```

## domainとinfrastructureの対応

Port and Adapter（ヘキサゴナルアーキテクチャ） の用語で、

- domainのinterface = Port（アプリケーションが外に求める口）
- infrastructureの実装 = Adapter（その口に具体技術を差し込むもの）

です。ファイル名を揃えるのは「Portに対応するAdapterが一目で分かる」ためで、Screaming Architecture（ディレクトリやファイル名が、フレームワークではなく業務の構造を叫んでいる状態）の実践と

Bad

```
domain/
└── target_user_repository.go
infrastructure/
└── mysql.go
```

Good

```
domain/
└── target_user_repository.go
infrastructure/
└── target_user_repository.go
```

## センチネルエラー

センチネルエラーを利用していくマインドである。

Bad

```go
if err != nil && err.Error() == "target user not found" {
    // ...
}
```

Good

```go
// domain
var ErrTargetUserNotFound = errors.New("target user not found")

// 呼び出し側
if errors.Is(err, domain.ErrTargetUserNotFound) {
    // ...
}
```
