### DBにてENUMを積極採用する _(2026/05)_

3値以上を扱う場合、DBカラムにENUMを積極採用。APIレスポンスも意味のある値で返す。
数値での識別はコメントや別資料の参照が必要となり、可読性が悪化するアンチパターン。可能な限りENUMを検討する。

**既存ロジックがある場合:** DBカラムは変更なし（影響大）。レスポンスはbreaking changeでなければ変更可。
**新規ロジック:** ENUMを積極採用。

**Tradeoff:**
    - Pros: ✅ DBを見ただけで意味がわかり、エンジニア以外も含め可読性が向上
    - Cons: ⚠️ 値変更がDDL変更になるため、[ENUMの特性](https://dev.mysql.com/doc/refman/8.0/ja/enum.html)を理解した上で採用すること

### Webのファイルパス命名規則を `kebab-case` に統一 _(2026/06)_

ディレクトリ・ファイルパスに `kebab-case` / `camelCase` / `snake_case` の3種類が混在していた状態を解消する。

**決定:** 新規ファイル・ディレクトリは全て `kebab-case` で定義する。既存も移行可能なタイミングで順次 `kebab-case` に移行していく。

**理由:**
- API Routes はURLとして露出するため `kebab-case` が必須
- ファイルベースルーティングを採用するフロントエンドもURLとの一貫性から `kebab-case` が適切
- Linux環境では `PascalCase` / `camelCase` のファイル名がモジュール解決エラーになる典型的なバグがある
- Next.js・React・Node.js の慣例に沿っている

**注意点:** 既存ファイルのリネームは影響範囲を確認してから行うこと。import パスの一括置換が必要になる場合がある。

### ADRを外部ツール管理 + リポジトリにサマリ参照を置くパターン _(2026/08)_

ADRをNotionなどの外部ドキュメントツールで管理しているプロジェクトで、リポジトリ側からもADRの存在を検知できるようにする運用パターン。

**決定:** マスタは外部ツール（Notion等）に置き、リポジトリの `docs/adr/` にはサマリ+外部ツールへの参照リンクだけを配置する。

**構成:**
- `docs/adr/README.md` に位置づけ・命名規則・一覧表を記載
- 個別ADRは `docs/adr/NNNN-english-slug.md`（連番4桁+ケバブケース）で作成
- 各ADRファイルの冒頭にMasterリンクとして外部ツールのURLを明記

**個別ADRのフォーマット:**

```markdown
# ADR-NNNN: タイトル

| 項目 | 内容 |
| --- | --- |
| Date | YYYY-MM-DD |
| Master | [外部ツールのリンク] ← 詳細・経緯のマスタはこちら |

## Context
背景と課題。

## Decision
決定事項。

## Consequences
採用による影響。

## Other Options（不採用案）
検討したが不採用とした選択肢とその理由。
```

**メリット:**
- PRレビューやコード読解の場でADRの方針をすぐ参照できる
- 外部ツールを使わないメンバーにもADRの存在が伝わる
- 詳細な議論・比較検討は外部ツール側で自由に更新できる

**注意点:**
- リポジトリ側の更新は結論の要約が変わったときだけ。詳細の追記や議論の更新は外部ツール側のみで行う
- README.mdの一覧表は新規ADR追加時に忘れず更新する

### wikiのAI検索をAsk AI + Gemini無料枠で構築 _(2026/07)_

wiki.nitaking.devにAI検索を導入するにあたり、Inkeep等の有料SaaSではなく、fumadocs公式のAsk AIテンプレート＋自前APIルートの構成を選んだ。

**決定:** fumadocs CLIでscaffoldしたAsk AIチャット（AISearch系コンポーネント＋`/api/chat`）を採用。LLMはGemini API無料枠（`@ai-sdk/google`、既定 `gemini-3.6-flash`、`GEMINI_MODEL` で変更可）を使い、回答はFlexSearchの検索ツールでwiki本文にグラウンディングする。あわせて `llms.txt` / `llms-full.txt` / `.mdx` サフィックスのMarkdownルートも公開し、外部AIエージェントからも読める形にした。

**理由:**
- Gemini無料枠（10リクエスト/分・1,500リクエスト/日程度）で個人wikiのトラフィックには十分。ランニングコストゼロ
- OpenRouterの `:free` モデルは無料モデルの入れ替わりが激しく運用が不安定
- 検索インデックスは既存の `/api/search` と同じFlexSearchで完結し、外部サービス依存がない

**注意点:**
- モデルIDは世代交代で廃止されることがある。動かなくなったら `GEMINI_MODEL` を新しいFlash系IDに差し替える
- AI SDK v7ではsystemプロンプトを `instructions` オプションで渡す（messages配列にsystem roleを入れるとエラー）
- Ask AIコンポーネントは `useEffectEvent` を使うためReact 19.2以上が必要
